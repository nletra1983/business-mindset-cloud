# Contract: Telegram voice message to text flow

Нового публичного HTTP API не добавляется. Контракт описывает поведение входящих Telegram update и внутренний интерфейс voice→text перед существующим text-flow.

## Input event contract

- Message update содержит `message.voice` (микрофонное voice-сообщение).
- Сценарии `message.audio` и `message.video_note` не обрабатываются как voice-input этой истории.

## Processing contract

1. Определить `person_id` и текущую модель человека.
2. Если voice-path для этой модели не поддержан:
   - ответ: `Эта модель не разбирает голос.`
   - run/profile step не изменяется
   - распознанная реплика не создаётся
3. Если voice-path поддержан, но текста нет:
   - ответ: `Голос не разобран.`
   - run/profile step не изменяется
   - распознанная реплика не создаётся
4. Если текст распознан:
   - бот отправляет распознанный текст отдельным сообщением без подписи
   - этот текст передаётся в тот же path, что `message.text`
   - шаг хода/профиля меняется только по действующим текстовым правилам

## Dedup contract

- Повторная доставка одного `update_id` не выполняет обработку второй раз (существующий `processed_telegram_update`).

## Persistence contract

- Хранится только итоговый текст (через существующий text-flow).
- Исходный audio payload после обработки не сохраняется.
