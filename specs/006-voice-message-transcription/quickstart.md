# Quickstart: voice message becomes text

Проверка проводится в существующем Telegram-контуре без нового сервиса.

## Preconditions

- Бот запущен в текущем контуре.
- Доступны переменные Telegram и модельные ключи, уже используемые контуром.
- Есть тестовый пользователь с рабочим диалогом в Telegram.

## Validation scenarios

1. Отправь микрофонное voice-сообщение в месте, где бот обычно принимает текст.

Ожидание: бот присылает распознанный текст отдельным сообщением без подписи, затем обрабатывает его как обычный текст.

2. Повтори сценарий внутри открытого хода разбора.

Ожидание: step progression совпадает с тем, как если бы текст был набран вручную.

3. Повтори сценарий в шаге редактирования профиля (`информация о себе`).

Ожидание: профильные промпты и сохранение ведут себя как для typed text.

4. Выбери модель без подтверждённого voice-path и отправь voice.

Ожидание: `Эта модель не разбирает голос.`, шаг хода/профиля не меняется.

5. Смоделируй пустой результат распознавания.

Ожидание: `Голос не разобран.`, шаг хода/профиля не меняется.

6. Отправь повторно тот же update (`update_id`) из канала.

Ожидание: обработка не выполняется второй раз, шаг не сдвигается повторно.

7. Отправь `audio` файл и `video_note`.

Ожидание: они не считаются voice-входом этой истории.

## Pass criteria

- Voice→text path не ломает существующий text-flow.
- Unsupported/empty cases дают recoverable ответы без побочных изменений состояния.
- Хранится только текстовая реплика; audio payload не сохраняется.
