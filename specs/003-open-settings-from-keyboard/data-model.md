# Data Model: Открыть настройки с клавиатуры разбора

История не добавляет новые таблицы или поля в БД. Ниже описаны логические сущности и переходы, которые уже есть в контуре и используются для этой функциональности.

## Existing entities used by the story

## Person

- Идентифицируется внутренним id (Telegram id остаётся привязкой, не ключом доменной записи).
- Содержит текущие настройки, включая уже существующий выбор модели.
- В этой истории не получает новых полей.

## Run

- Хранит шаг, статус и транскрипт текущего разбора.
- Критичное правило: открытие `настройки` не изменяет шаг и статус.
- В этой истории не получает новых полей.

## Logical UI entities (non-persisted)

## Interaction Context

- Один из контекстов, в которых допускается вход в настройки:
  - незавершённый ход;
  - список ходов;
  - после финала.
- Используется для проверки, что действие `настройки` вызвано из поддерживаемой точки.

## Settings Menu

- Логический первый уровень настроек с двумя пунктами:
  - `выбор модели`;
  - `информация о себе`.
- В этой истории — только точка входа и выбор направления, без полной реализации второй ветки.

## State transitions

1. Пользователь нажимает `настройки` в поддерживаемом контексте.
2. Система показывает меню из двух пунктов.
3. При выборе `выбор модели` управление передаётся в существующий поток выбора модели.
4. При выборе `информация о себе` управление передаётся в entry-point следующей истории (без изменения run-состояния в текущей истории).
5. Если нажатие пришло из неподдерживаемого/устаревшего контекста, система отдаёт recoverable-ответ и не меняет состояние `Run`.

## Invariants

- Нажатие `настройки` не создаёт новый ход.
- Нажатие `настройки` не завершает текущий ход.
- Нажатие `настройки` не изменяет историю реплик.
