# Quickstart: hidden profile update from exercise result

Проверка проводится на существующем Telegram-контуре и pytest-наборах.

## Preconditions

- История `004-self-info-profile` уже внедрена (visible profile flow отделён).
- Бот и Postgres запущены в текущем окружении.
- Для тестового пользователя можно завершить хотя бы один ход упражнения.

## Validation scenarios

1. Заверши ход, где упражнение передаёт наблюдение только для `spotting`.

Ожидание: hidden-профиль обновляет только `spotting`; остальные пять характеристик не меняются.

2. Повтори завершение хода с тем же направлением сигнала для `spotting` во втором завершённом ходе.

Ожидание: статус `spotting` переходит в `устойчиво`.

3. Отправь в следующем ходе противоположный сигнал для `spotting`.

Ожидание: статус `spotting` становится `неравномерно`; в истории остаются оба свидетельства.

4. Переотправь тот же результат (`run_id`, `characteristic_id`) повторно.

Ожидание: дубликат свидетельства не создаётся; статус не дрейфует.

5. После hidden-обновления открой `информация о себе` и сделай правку visible профиля.

Ожидание: hidden-статусы и внутренние ids не показываются пользователю; правка visible-профиля не меняет hidden-статусы.

## Pass criteria

- Обновления hidden-профиля происходят только по валидным наблюдениям упражнения.
- Merge-правила статусов выполняются детерминированно.
- Идемпотентность повторной доставки выдержана.
- Граница приватности hidden/visible профиля сохранена.
