# Contract: обновление hidden skill profile по результату задания

Публичный HTTP API не добавляется. Контракт внутренний: как результат упражнения передаётся в слой профиля и какие гарантии даёт обработчик.

## Trigger

- Обработчик вызывается при завершении хода упражнения.
- Обработчик может вызываться повторно для того же `run_id` (повторная доставка/ретрай).

## Input payload (logical contract)

- `run_id`
- `person_id`
- `exercise_id`
- `observations[]`:
  - `characteristic_id` (`spotting|creativity|valuing|uncertainty|resources|learning`)
  - `signal` (`проявляется|слабо`)
  - `quote_or_paraphrase`

## Validation rules

- Для неподдерживаемого `characteristic_id` обновление отклоняется без изменения persisted профиля.
- Для неподдерживаемого `signal` обновление отклоняется без изменения persisted профиля.
- Для короткого разбора (`exercise_id` smoke-варианта) разрешено обновлять только `spotting`.

## Merge rules

- Если текущий статус `не наблюдалось`, первый сигнал ставит `проявляется` или `слабо`.
- Если во втором завершённом ходе сигнал повторяется, статус становится `устойчиво`.
- Если новый сигнал противоположный ранее зафиксированному, статус становится `неравномерно`, оба свидетельства сохраняются.
- Один завершённый ход не ставит `устойчиво`.

## Idempotency rules

- Повтор той же пары (`run_id`, `characteristic_id`) не создаёт вторую запись свидетельства.
- Повтор не должен менять статус профиля иначе, чем первый успешный приём.

## Output guarantees

- Ровно один `current_focus` выбран из шести характеристик.
- Hidden-профиль обновлён только по характеристикам из валидных наблюдений.
- User-visible профиль (`информация о себе`) и его поля не изменяются этим обработчиком.
