# Data Model: Обновлять скрытый файл профиля по результату задания

История описывает внутреннюю (непоказываемую человеку) модель профиля навыка и правила записи свидетельств из результатов упражнения.

## HiddenSkillProfile

Одна запись на человека с текущим состоянием характеристик и полем фокуса.

## Fields

- `person_id` — внутренний идентификатор человека (уникальный ключ профиля).
- `spotting_status` — статус характеристики «замечать возможность».
- `creativity_status` — статус характеристики «держать разные ответы».
- `valuing_status` — статус характеристики «отличать то, за что платят».
- `uncertainty_status` — статус характеристики «действовать при неполных данных».
- `resources_status` — статус характеристики «опираться на то, что уже есть».
- `learning_status` — статус характеристики «учиться на проверке».
- `current_focus` — одна характеристика из шести, выбранная как `сейчас тренировать`.
- `updated_at` — время последнего пересчёта профиля.

## Constraints

- Допустимые статусы для каждой характеристики: `не наблюдалось`, `проявляется`, `слабо`, `устойчиво`, `неравномерно`.
- `current_focus` всегда ссылается только на одну из шести характеристик (не отдельная седьмая характеристика).
- `устойчиво` не может появиться после единственного свидетельства в одном завершённом ходе.

## CharacteristicEvidence

История наблюдений по характеристикам, на основании которой рассчитываются статусы.

## Fields

- `person_id` — владелец профиля.
- `run_id` — ход, из которого пришло наблюдение.
- `characteristic_id` — одна из шести характеристик.
- `signal` — направление наблюдения (`проявляется` или `слабо`).
- `quote_or_paraphrase` — цитата или короткий пересказ ответа человека.
- `exercise_id` — упражнение/версия, которая дала наблюдение.
- `recorded_at` — время записи свидетельства.

## Constraints

- Уникальность `(run_id, characteristic_id)` для идемпотентной повторной доставки.
- Свидетельство не создаётся для характеристик, которые не наблюдались в этом ходе.
- Сигнал хранится только как наблюдение упражнения, а не как произвольная ручная правка.

## ExerciseProfileObservation (input model)

Структурированный вход в обновление профиля из результата упражнения.

## Fields

- `run_id`
- `person_id`
- `exercise_id`
- `observations[]`:
  - `characteristic_id`
  - `signal`
  - `quote_or_paraphrase`

## Constraints

- Для короткого разбора допускается только `spotting`.
- Пустой список наблюдений не меняет hidden-профиль.

## VisibleProfileDocument (boundary check)

User-visible профиль (`информация о себе`) остаётся отдельной сущностью.

## Constraints

- Обновления hidden-профиля не изменяют поля visible-профиля.
- Правки visible-профиля не изменяют статусы hidden-профиля.
