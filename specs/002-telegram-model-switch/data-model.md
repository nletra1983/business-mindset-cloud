# Data Model: Переключение модели в разборе

Логические записи. Новых таблиц нет. Статус «пауза» не добавляется. Удаления записей нет.

Имена запросов: `deepseek-chat`, `GigaChat-2`, `glm-5.3-flash`.

## person (уже есть, два поля)

| Поле | Тип | Правило |
|---|---|---|
| `current_model` | text NOT NULL | Текущая модель человека. Пока он сам не выбирал — `deepseek-chat`. Меняется нажатием кнопки и правилом отката после двух неудач. |
| `last_answered_model` | text NULL | Последняя из трёх моделей, чей вызов вернул текст. Пусто, пока ни одна не отвечала. При откате `current_model` становится этим значением. Если пусто, подставлять некого. |

Остальные поля человека и привязка Telegram user id не меняются. User id ключом человека не становится.

## run (уже есть)

`model_requested` — модель следующего вызова этого хода. При смене текущей модели у человека открытый ход обновляет это поле. Уже записанные реплики не переписываются.

`model_returned` — имя из ответа провайдера, если оно есть. На кнопках человека не показывается.

`access_mode` остаётся `service_free`.

`status` по-прежнему только `open` или `completed`. Неудача модели статус не меняет на завершённый и не вводит паузу.

Завершённый ход при последующей смене модели не обновляется: ни ответы, ни финал, ни `model_requested`.

## utterance (уже есть)

Реплики не получают отдельное поле модели. Смена модели их не меняет.

## run_summary (уже есть)

Сводка пишется при завершении, как сейчас. Недоступность модели сводку не создаёт и уже записанную сводку не пересчитывает.

## Переходы

1. Человек ещё не выбирал: `current_model = deepseek-chat`, `last_answered_model` пусто.
2. Нажата другая модель: `current_model` становится её id. Если есть открытый ход, его `model_requested` становится тем же id. Реплики на месте.
3. Вызов вернул текст: `last_answered_model` становится запрошенным id. `model_returned` пишется, если провайдер его вернул.
4. Вызов не вернулся, повтор того же вызова тоже не вернулся, и `last_answered_model` заполнен: `current_model` становится `last_answered_model`. Открытый ход, если он есть, получает тот же `model_requested`. Статус хода не меняется.
5. Тот же двойной обрыв, и `last_answered_model` пусто: `current_model` не подменяется. Ход остаётся незавершённым.
