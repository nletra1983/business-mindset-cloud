# Contract: `/app/v1` channels entrance

Один хост сервиса бота. Путь начинается с `/app/v1`. Тело — JSON. Ответы — JSON.

## POST `/app/v1/auth/email/request`

Тело: `{ "email": "..." }`  
Успех: код ушёл, Telegram не требуется.  
Ошибка адреса или отправки: человек снаружи, секрет не выдан.

## POST `/app/v1/auth/email/confirm`

Тело: `{ "email": "...", "code": "..." }`  
Успех: `{ "session_secret": "..." }` и человек внутри.  
Неверный или старый код: секрета нет.

## GET `/app/v1/runs`

Заголовок: `Authorization: Bearer <session_secret>`  
Ответ: список ходов этого входа (может быть пустым).

## POST `/app/v1/runs`

Заголовок сессии. Опционально `Idempotency-Key`.  
Тело: `{ "topic": "..." }` — начать разбор своей формулировкой.

## POST `/app/v1/runs/{run_id}/resume`

Заголовок сессии. Вернуться в незаконченный ход.

## POST `/app/v1/runs/{run_id}/answers`

Заголовок сессии. Опционально `Idempotency-Key`.  
Тело: `{ "text": "..." }` — ответ на текущий шаг. Повтор ключа не двигает шаг второй раз.

## GET `/app/v1/settings` и связанные действия модели / профиля / второго входа

Заголовок сессии. Вызывают уже принятые правила настроек. Не открывают второй хост.

## Без секрета

Любой путь после входа без действующего секрета — отказ, ход не двигается.
