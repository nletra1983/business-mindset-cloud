# Research: вход каналов для приложения

## Decision: один процесс, stdlib HTTP, путь `/app/v1`

**Decision**: Слушатель `http.server` в фоновом потоке того же процесса, что Telegram long poll. Путь продукта — `/app/v1/...`. Новый веб-фреймворк не добавляем.

**Rationale**: Конституция запрещает второй сервис. Зависимостей в `requirements.txt` три; FastAPI/Flask раздули бы стек без нужды.

**Alternatives considered**: Отдельный контейнер API. Отклонено: второй процесс. ASGI-фреймворк. Отклонено: лишняя зависимость.

## Decision: TLS на краю хоста, процесс слушает локально

**Decision**: Процесс принимает HTTP на адресе контейнера/localhost. Снаружи человек и приложение видят HTTPS того же хоста сервиса бота: край хоста (прокси) завершает TLS и отдаёт `/app/` внутрь. В compose порт публикуется на `127.0.0.1`.

**Rationale**: ADL-021 — один хост. Контейнер бота сейчас не обязан сам держать сертификаты.

**Alternatives considered**: HTTPS прямо в Python. Отклонено: сертификаты и обновления на Selectel уже логичнее на краю.

## Decision: секрет сессии после верного кода

**Decision**: После `confirm` выдаётся непрозрачный секрет. В базе хранится только его хеш. Последующие запросы несут секрет в заголовке. Отзыв — история №3; здесь достаточно поля `revoked_at`, чтобы №3 не ломала схему.

**Rationale**: Спека требует секрет после подтверждения и отказ без него.

**Alternatives considered**: Только cookie без явного секрета. Отклонено: мобильный клиент проще с явным секретом (№3 кладёт его в хранилище платформы).

## Decision: ключ повтора операции

**Decision**: Клиент может прислать `Idempotency-Key`. Пара «человек + ключ» помнит уже отданный ответ. Повтор не двигает шаг второй раз.

**Rationale**: Спека US3. У бота уже есть `processed_telegram_update`; приложению нужен свой ключ, не update_id Telegram.

**Alternatives considered**: Дедуп только по тексту ответа. Отклонено: два разных шага с одинаковым текстом возможны.
