# Research: Короткий разбор автора в Telegram

Решения ниже либо названы человеком, либо закрыты 2026-10-23 после уточнений и по факту уже работающего контура Selectel. Библиотеки и облако заново не выбирались.

## Язык

- Decision: Python
- Rationale: назван во входе `/speckit-plan`; менять только при явной дыре в спеке. Такой дыры нет.
- Alternatives considered: не рассматривались

## Версия Python

- Decision: 3.12
- Rationale: на сервере уже собирался образ `python:3.12-slim` для пробы канала; совпадает с рабочим контуром.
- Alternatives considered: 3.11 / 3.13 — без причины менять уже проверенный major

## Библиотеки Telegram, Postgres и HTTP

- Decision: без тяжёлого фреймворка бота. HTTP к Telegram API и DeepSeek — `httpx`. Postgres — `psycopg` (v3, binary). Скилл — файл markdown в образе/volume, парсинг минимальный под smoke.
- Rationale: спека не требует webhook-сервера; long poll + прямые вызовы API уже доказаны с хоста через CF-прокси. ORM и aiogram/python-telegram-bot не обязательны для одного процесса.
- Alternatives considered: `urllib` как в echo — оставить можно, но `httpx` проще таймауты/повторы; SQLAlchemy — лишняя сложность на один срез

## Проверка

- Decision: `pytest` на логику хода (оценка достаточного/слабого, идемпотентность update id, переходы статусов) без обязательного живого Telegram в CI.
- Rationale: инструмент во входе не был назван; pytest — стандарт для Python 3.12, не меняет стек продукта.
- Alternatives considered: только ручной quickstart — недостаточно для SC по шагу и update id

## Как приходят update Telegram

- Decision: long poll `getUpdates` через `TELEGRAM_API_BASE` (как рабочая проба echo). Webhook на Selectel в этот срез не входит.
- Rationale: с хоста прямой `api.telegram.org` недоступен; прокси уже есть; публичный HTTPS до Selectel для webhook не настраивался.
- Alternatives considered: webhook на CF → Selectel — отдельный срез инфры

## Идентификатор модели DeepSeek

- Decision: запрос с `model=deepseek-chat` (как успешный вызов с хоста 2026-10-23). Фактическое имя в ответе API может отличаться — в ход писать то, что вернул провайдер, плюс запрошенный id.
- Rationale: спека: id в секретах/данности; с хоста уже проверено.
- Alternatives considered: другие id DeepSeek — не нужны в smoke

## Путь к ключу DeepSeek

- Decision: в контейнере — `/opt/business-mindset/secrets/deepseek.env`, переменная `DEEPSEEK_API_KEY`. В репозитории для локали — `.secrets/deepseek.env` (в git не коммитить). Compose монтирует `./secrets` или копирует с сервера как сейчас.
- Rationale: на сервере файл уже приведён к `DEEPSEEK_API_KEY=`; локальный каталог `.secrets/` уже есть.
- Alternatives considered: один общий `.env` — хуже изоляции

## Каталог кода

- Decision: `app/` в корне репозитория `D:\Business_mindset` (пакет приложения). Деплой: содержимое уходит в `/opt/business-mindset/app` на сервере, тот же `docker-compose`, сервис `bot` вместо echo.
- Rationale: конституция — код в этом репозитории; на сервере каталог `app` уже заведён.
- Alternatives considered: `src/`, отдельный git-репо — лишнее для одного человека

## Оценка и выбор модели

- Decision: в этом срезе единственная разрешённая модель аккаунта — DeepSeek (бесплатный путь сервиса). Диалог (вопросы), оценка достаточности ответа и финал идут ею же; критерии оценки — из smoke-скилла, в промпт судьи. Локальные эвристики gate не используются (решение 2026-10-24). Отдельный UI выбора модели не делается. Расхождение с формулировкой конституции «модель, которую выбрал человек» снимается так: система назначает единственную доступную в MVP; когда появится список — выбор человека совместим с той же схемой «разрешённые модели аккаунта».
- Rationale: спека среза + уточнение после plan + выбор человека 2026-10-24.
- Alternatives considered: второй судья-модель — запрещён ADL-007 / спекой; локальный gate — отклонён для первого выклада

## Три способа доступа в данных

- Decision: в записи хода (или вызова) хранить поле режима доступа со значением `service_free` для этого среза. Значения `user_key` и `service_paid` в схеме допустимы как зарезервированные, сценарии не реализуются.
- Rationale: конституция — не ломать модель данных трёх способов; спека строит только бесплатный путь.
- Alternatives considered: не писать режим совсем — сломает шов позже
