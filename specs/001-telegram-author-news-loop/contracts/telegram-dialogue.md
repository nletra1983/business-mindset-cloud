# Contract: окно хода в Telegram

Нового HTTP API этот срез не публикует. Наружу — диалог бота. Внутрь — один вызов DeepSeek с сервера.

## Вход из Telegram

- Транспорт: только `TELEGRAM_API_BASE`. Прямой Bot API с Selectel не используется.
- Секрет бота: переменная `TG_GETBUSINESSIDEA_TOKEN`. Значение в контракт не входит.
- На сообщении нужны Telegram user id, ник, текст и update id.
- Способ получения update: long poll `getUpdates` через `TELEGRAM_API_BASE`. Webhook в этот срез не входит.

Повтор того же update id не меняет шаг, не создаёт вторую реплику и не вызывает модель второй раз.

## Окно хода

- У хода одно окно.
- Первое сообщение — формулировка человека. Оно запинено и остаётся видимым.
- Любое следующее сообщение в этом окне — ответ на этот ход.
- Пустой или бессодержательный первый ввод ход не открывает. Человека просят сформулировать снова. Событие не выдумывается.
- Сообщение-ссылка страницу не загружает.
- Пока агент формулирует, человек видит, что агент занят.
- Пока ход ждёт человека, человек видит, что ждут его.
- Молчание ход не закрывает.

## Речь агента

- Один вопрос за раз, по smoke-скиллу, версия `business-idea-from-news.smoke`.
- Порядок: событие, масштаб, короткий финал.
- Слабый ответ: одно предложение, чего не хватает, и тот же вопрос.
- Финал: что получилось, что слабо, что пропущено. Те же три пункта пишутся в сводку хода.
- Сводку навыка и передачу в профиль агент не делает.
- Готовых идей продукта до финала нет.

## Выход и второй ход

- Отдельного статуса «пауза» нет. Незавершённый ход хранит шаг. Следующее слово за человеком — обычное состояние такого хода.
- Выход из окна: кнопка «к другим вопросам». Она показывает список незавершённых ходов. Шаг прежнего хода на месте.
- Новый ход со своей запиненной формулировкой начинается из этого списка.
- Возврат: клик по ходу в списке. Открывается тот же ход, а не новый.

## Вызов модели

- Вызывает только сервер.
- Ключ: `secrets/deepseek.env` по фразе человека. Фактический путь файла в рабочей копии другой; см. research.md.
- Диалог и оценка — один и тот же вызов этого среза. Человек модель не выбирает и не меняет.
- Нет ответа: один повтор того же вызова.
- Второй обрыв: ход остаётся не завершён, человеку сказано о проблемах со связью и предложено продолжить позже.
- Идентификатор модели в запросе: `deepseek-chat`. В ход писать также `model_returned` из ответа API, если есть.
