# Data model: Короткий разбор автора в Telegram

Логические записи среза. Имена таблиц и типы ниже — решение реализации 2026-10-23 (закрытие NEEDS CLARIFICATION); менять только при дыре в спеке.

## Человек (`person`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID PK | Внутренний идентификатор, ключ человека |
| `accepting_new` | boolean | После «к другим вопросам»: следующее сообщение — новая формулировка |
| `created_at` | timestamptz | |

Telegram user id ключом не является. Возраст не хранится.

## Привязка канала (`channel_link`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID PK | |
| `person_id` | UUID FK → person | |
| `channel` | text | В срезе всегда `telegram` |
| `telegram_user_id` | bigint UNIQUE | Привязка, не ключ человека |
| `telegram_username` | text null | Ник; может смениться |
| `updated_at` | timestamptz | |

Один `telegram_user_id` — одна строка. Смена ника обновляет `telegram_username`, не создаёт человека.

## Ход (`run`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID PK | |
| `person_id` | UUID FK → person | |
| `status` | text | `open` \| `completed` (отдельного `paused` нет) |
| `step` | text | `awaiting_topic` не храним: до создания хода. В ходе: `event` \| `scale` \| `finalizing` → затем `completed` |
| `skill_version` | text | `business-idea-from-news.smoke` |
| `topic_text` | text | Исходная формулировка |
| `access_mode` | text | В срезе `service_free`; зарезервированы `user_key`, `service_paid` |
| `model_requested` | text | Запрошенный id, для среза `deepseek-chat` |
| `model_returned` | text null | Имя модели из ответа API, если есть |
| `telegram_chat_id` | bigint | Окно диалога |
| `pinned_message_id` | bigint null | Id запиненного сообщения с формулировкой |
| `in_window` | boolean | Сообщения чата сейчас идут в этот ход |
| `event_answer` | text null | Принятый ответ блока «событие» (после оценки DeepSeek) |
| `scale_answer` | text null | Принятый ответ блока «масштаб» |
| `created_at` | timestamptz | |
| `updated_at` | timestamptz | |

Один ход — одна формулировка. У человека в срезе может быть несколько `open` (после «к другим вопросам»), но сообщения в окне текущего хода идут только в него.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID PK | |
| `run_id` | UUID FK → run | |
| `speaker` | text | `human` \| `agent` |
| `text` | text | |
| `created_at` | timestamptz | |

Транскрипт отдельно от состояния хода и от сводки.

## Сводка хода (`run_summary`)

| Поле | Тип | Смысл |
|---|---|---|
| `run_id` | UUID PK FK → run | Одна сводка на завершённый ход |
| `what_worked` | text | |
| `what_weak` | text | |
| `what_missed` | text | |
| `created_at` | timestamptz | |

Появляется только при `status = completed`. Не профиль навыка.

## Уже обработанный update id (`processed_telegram_update`)

| Поле | Тип | Смысл |
|---|---|---|
| `update_id` | bigint PK | Telegram update id |
| `processed_at` | timestamptz | |

До обработки апдейта — проверка наличия. Если есть — выход без сдвига шага, без второй реплики, без второго вызова модели. После успешной обработки — insert.

## Служебное (`bot_kv`)

| Поле | Тип | Смысл |
|---|---|---|
| `key` | text PK | Например `offset` для long poll |
| `value` | text | |

Не предметная сущность продукта; нужна процессу long poll.

## Переходы

- Пустая или бессодержательная формулировка ход не создаёт.
- Содержательная формулировка открывает ход на шаге `event` и становится запиненным первым сообщением окна.
- Достаточный ответ: `event` → `scale` → финал → `completed`.
- Слабый ответ оставляет тот же `step`.
- Кнопка «к другим вопросам» и второй подряд обрыв вызова модели оставляют ход `open`. Шаг сохраняется. Короткий след не пишется. Статуса «пауза» нет.
- Молчание, пока ход ждёт человека, состояние и шаг не меняет.
- Клик по незавершённому ходу в списке продолжает тот же ход.
- Сообщение внутри окна текущего хода новый ход не создаёт.
- Новый ход начинается из списка после «к другим вопросам». Прежний остаётся `open`.
- Повтор того же `update_id` переход не вызывает.
- Час недоступности тренировку прерывает. Уже принятый ход остаётся.

## Вне модели этого среза

Профиль навыка, скрытый след, снимок страницы, карточка прошлого разбора, оплата, свой ключ, второй канал.
