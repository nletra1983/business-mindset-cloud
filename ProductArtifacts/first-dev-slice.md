# Первый срез разработки

Дата: 2026-10-23  
Статус: к specify (граница согласована человеком — после «шаг 4 готов»)

## Имя среза (для Spec Kit)

`telegram-author-news-loop`

## Зачем этот срез

Заменить эхо-бота рабочим контуром автора: Telegram → аккаунт → ход разбора → ответ по скиллу → запись в Postgres. Инфра (Selectel, Postgres, CF-прокси, секреты) уже есть.

Вход в разбор в этом срезе — не ссылка, а краткая формулировка новости или проблемы, которую вводит сам человек (что его блокирует / о чём думает).

## Входит

1. Первый вход автора из Telegram: создать внутренний идентификатор, привязать Telegram user id и ник; повторные сообщения — тот же аккаунт.
2. Из текущего хода новый не начинается. В окне хода запинено первое сообщение — формулировка, с которой ход начался. Все сообщения в окне отвечают на этот ход. Кнопка «к другим вопросам» закрывает окно и показывает список незавершённых ходов. Новый ход начинается из этого списка. Возврат — клик по ходу в списке: тот же шаг, те же реплики, та же версия скилла. Отдельного статуса «пауза» нет.
3. Начать разбор с текста человека: краткая формулировка новости или проблемы. Пустой или бессодержательный ввод — попросить сформулировать снова; событие и факты сервис не выдумывает сверх сказанного человеком.
4. Вести разбор по **smoke-скиллу** `features/business-idea-from-news/FeatureArtifacts/business-idea-from-news.smoke.md`: ровно два вопроса (событие → масштаб), затем короткий финал и завершение хода. Слабый ответ не пускает дальше. Опора — формулировка человека, не страница сайта. Полный скилл `business-idea-from-news.md` в этом срезе не подключать; подмена на полный — отдельным шагом после стабильного контура (конфиг/путь к файлу скилла).
5. Вызов модели с сервера из списка «бесплатные» (конкретные id моделей — в реализации/секретах; пока достаточно DeepSeek, уже проверенного с хоста).
6. Хранить в Postgres: человека, привязку канала, ход (шаг, статус, версия скилла, исходная формулировка), транскрипт реплик и при завершении отдельную сводку этого хода (три пункта финала, не профиль навыка).
7. Тот же Docker-контур на Selectel; Telegram только через `TELEGRAM_API_BASE` (CF-прокси).
8. Повторная доставка того же update id MUST NOT сдвигать шаг.
9. Отдельного статуса «пауза» нет. Незавершённый ход хранит шаг, следующее слово за человеком. Обрыв сессии и кнопка «к другим вопросам» ход не завершают. Короткий след не пишется. Молчание, пока ход ждёт человека, ход не завершает.
10. Вызов модели не вернул ответ — один повтор того же вызова. Второй обрыв оставляет ход незавершённым. Человеку сказано о проблемах со связью и предложено продолжить позже. Модель в ходе не меняется.
11. Час недоступности прерывает тренировку. Уже принятый ход сохраняется. Отдельного офлайн-хода нет.
12. Ник может смениться и ключом человека не является. Возраст при входе не спрашивается. Пока агент формулирует, человеку видно, что агент занят. Пока ход ждёт человека — что ждут его.

## Не входит (следующие срезы / фичи)

- Приём ссылки на новость и загрузка/сужение текста страницы (отдельный функционал сужения контекста — позже).
- Мобильное приложение, браузер, Макс.
- Слияние профилей кодом, удаление аккаунта (полный сценарий account-management).
- Карточка завершённого разбора со сводкой и лентой. Список незавершённых ходов в срез входит: клик по ходу возвращает в него.
- Повторный разбор той же темы отдельной записью.
- Смена модели внутри хода (в данных место заложить можно, UI/сценарий — позже).
- Подборка новостей по сайтам из скилла.
- Платные модели, свой ключ человека, оплата.
- Кабинет наставника.
- Скрытый след навыка и профиль навыка. Сводка этого хода в срез входит.
