# История: держать сессию входа на устройстве и дать явный выход

Граница этой истории. Запрос кода и первый вход по коду — соседние истории. Здесь только то, что остаётся на телефоне после верного кода, и выход.

## Зачем

Архитектура требует сессионный секрет в хранилище платформы. Нужно правило повторного открытия и выхода.

## Что входит

После верного кода секрет сессии лежит в аппаратном хранилище платформы, не в открытом файле. Ключ провайдера модели на устройство не попадает.

При следующем открытии приложения человек остаётся вошедшим и видит список ходов своего входа без нового кода. Сервис сам его не выкидывает по таймеру.

Явный выход есть и делается только по инициативе человека. При выходе:

1. сервер отзывает эту сессию — тот же секрет больше не принимается;
2. на устройстве секрет стирается.

После выхода снова нужен код из письма. Только стереть секрет на телефоне недостаточно: украденный или скопированный секрет иначе остался бы действительным.

## Что не входит

Выбор модели. Слияние входов. Сборка APK. Какая почта шлёт код. Сам HTTPS-вход — история №2.
