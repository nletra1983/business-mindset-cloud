# История: собрать Flutter-клиент и отдать автору подписанный APK

Граница этой истории. Правила входа, хода и настроек здесь не пишутся заново: клиент вызывает уже принятые серверные правила.

## Зачем

Без файла установки истории экранов нельзя проверить на телефоне. Решение ADL-020: один клиент на Flutter, первая поставка — подписанный APK автору, без магазина.

## Почему отдельно

История №5 про вход по email на экране. Файл установки, ключ подписи и идентификатор пакета — другая работа.

## Что входит

Проект клиента на Flutter в этом репозитории. Подписанный APK с одним идентификатором пакета. Ключ подписи хранится у автора вне git (как секреты). Установка на Android автора без магазина. Следующая версия ставится поверх с тем же ключом и тем же идентификатором пакета. Приложение ходит только во вход каналов из истории №2.

Готовый APK кладётся файлом на диск компьютера автора (в каталог сборки проекта). Передача через Telegram и магазины в эту историю не входят.

Минимальная платформа первой сборки — обычный актуальный Android на телефоне автора. Конкретный `minSdk` выбирает реализация по Flutter stable на дату сборки; отдельную старую ветку Android не поддерживаем.

## Что не входит

iOS. Google Play, RuStore, App Store. Карточка магазина. Оплата. Рассылка APK в мессенджер. Экраны разбора сверх каркаса, нужного чтобы открыть вход: полный UI историй №5–№8 может добираться ими после установки.
