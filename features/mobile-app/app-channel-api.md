# История: открыть защищённый вход модуля каналов для приложения

Граница этой истории. Правила email, слияния, разбора и настроек здесь не меняются: вызываются уже принятые.

## Зачем

Телефон не говорит с Telegram API и не вызывает модель. Ему нужен один защищённый вход в уже существующий модуль каналов.

## Почему отдельно

История №1 меняет только учётные привязки. Истории №5–№8 — экраны. Вход каналов — шов сервера между ними.

## Что входит

Сервер принимает запросы приложения по HTTPS в том же процессе и в том же российском контуре, что бот. Отдельный процесс и отдельная база не поднимаются.

Адрес хоста тот же, что у уже работающего сервиса бота в российском регионе. Другой домен и второй входной адрес не заводятся. Отличие канала — путь и контракт запросов приложения (не long poll Telegram). Конкретное имя пути выбирает реализация; продукт требует один хост и отдельный путь.

По этому входу приложение может: запросить код на email, подтвердить код, после подтверждения получить секрет сессии, дальше с этим секретом — список ходов, вести разбор, открыть настройки и слияние входов. Повтор той же входящей операции не двигает шаг второй раз. Ответам хватает правил, уже принятых для бота и для историй №1 и №5–№8.

Ключ провайдера модели и текст диалога в письмо по этому входу не уходят сверх уже принятого для кода.

## Что не входит

Экраны Flutter. Сборка APK. Выбор почтового провайдера. iOS. Магазины. Как секрет хранится на телефоне — история №3. Второй хост или отдельный сервис только для приложения.
