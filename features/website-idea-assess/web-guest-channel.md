# Граница истории №0: внедрить веб-канал лендинга на Selectel

**Блокирует** истории №1–№6: без DNS, раздачи страниц, гостевой сессии и крючков get-news/smoke API остальные экраны к живому серверу не подключить.

## Входит

- DNS: A `get-business-idea.ru` на IP Selectel того же сервера, что бот; `www` → на этот домен.
- В том же процессе: раздача лендинга (хотя бы каркас) и HTTP API гостя/хода; Telegram и `/app/` не ломаются.
- Гостевая сессия (cookie): билет, счётчик окон за день, текущее окно, лента TTL 24 ч от первой реплики; «Очистить» не обязана стирать сервер до TTL.
- Место под фон обновления бэклога get-news каждые 4 ч и под вызов smoke (полная UX-воронка — в следующих историях).
- `secrets/smartcaptcha.env`: `SMARTCAPTCHA_CLIENT_KEY`, `SMARTCAPTCHA_SERVER_KEY` → добавить `env_file` у `bot` в `docker-compose.yml`.
- Почта витрины/дня 2 — тот же контур, что `secrets/mail.env` (имена уже есть у приложения).
- `YANDEX_METRIKA_COUNTER_ID` — не секрет, в конфиге сайта/env приложения.
- Не менять спеки `specs/001`…`specs/014` задним числом.

## Не входит

- Полные блоки лендинга, гейт email, письмо дня 2, фейковая оплата, проверка капчи в UX — №1–№6.
- Значения секретов; заход агента на Selectel руками; выкладка только через `main` / publish.
- Эквайринг, баланс, расчёт трафика.
- Имя конкретной модели на экране (настройка шлюза).
