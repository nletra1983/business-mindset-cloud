# Этапы фичи

Напоминалки по этапам Product Architecture Framework для свойства продукта. Текст правится по ходу. В рабочие папки это не копировать.

Папка шага создаётся, когда шаг открыт, внутри `features/<имя>/FeatureLC/`. Шаги одной стадии лежат рядом, в исходном порядке. Имя папки совпадает с заголовком. Косая черта в имени заменена на ` - `.

Данные для работы фичи лежат рядом, в `features/<имя>/FeatureArtifacts/`. Список фич — `features/feature-map.md`.

Одинаковые названия в разных стадиях — разные папки. Их не склеивать.

У каждого шага пять атрибутов. Их читает автоматизация по `lifecycle/step-rules.md`.

- `Папка` — куда писать ответ человека.
- `Шаг` — имя для автоматизации. Если есть команда, имя совпадает с ней без `/`.
- `Команда` — как открыть шаг самому. `нет` — шаг открывается только автопереходом.
- `Текст пользователю` — что человек видит в чате на этом шаге.
- `Выход` — автопереход к коду из `Шаг` или список команд на выбор. В скобках автоперехода стоит код шага. Строка с `/` ссылается на команду, а код шага — эта команда без `/`. Пояснение после кода или команды на поиск не влияет. Название шага в ссылке не пишется.

После текста человек отвечает. Пока любой непустой ответ считается достаточным. Ответ пишется в `answer.md` в папке шага.

Строка «Исходное:» — прежняя короткая формулировка. Там, где текст пользователю ещё не переписан, в него пока подставлен прежний ориентир.
