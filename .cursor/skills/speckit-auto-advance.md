# Автопереход Spec Kit (Business Mindset)

Правило для `/speckit-specify`, `/speckit-plan`, `/speckit-tasks`, `/speckit-implement`. Цель: не срезать углы скиллов, но не ждать человека после каждого зелёного шага.

## Цепочка одной истории

Порядок только такой: **specify → plan → tasks → implement**.

После успешного завершения шага:

1. Если есть вопрос человеку, `[NEEDS CLARIFICATION: …]`, проваленный gate `/check-ready-to-speckit`, конфликт конституции или неоднозначный вход — **остановиться**. Следующий шаг не начинать.
2. Если ничего из пункта 1 нет — **сразу** выполнить следующий скилл той же спеки (той же папки `specs/…` / того же `.specify/feature.json`).
3. Перед каждым шагом читать и соблюдать полный `SKILL.md` этого шага (хуки, шаблоны, проверки). Автопереход не освобождает от скилла и не склеивает два шага в один «укороченный».
4. Две истории в один specify / один plan / одни tasks / один implement — **запрещены**.

`implement` входит в автопереход: при зелёном `tasks` агент переходит к реализации без ожидания «продолжай». Человек MAY в том же сообщении написать «остановись перед implement» — тогда после `tasks` стоп.

## Несколько историй подряд

Если человек назвал несколько историй (номера, названия) или сказал полный поток по списку ready:

- закончить цепочку первой истории до конца (или до стопа по вопросу);
- коротко написать в чат, какая история закрыта по Spec Kit;
- перейти к следующей истории с `/speckit-specify` (с gate штампа) **без** ожидания «можно следующую», если список уже дан;
- если список не дан — после одной полной цепочки остановиться.

## Что не считается «нет вопросов»

- Молчание человека в чате, пока агент ещё не завершил шаг.
- Догадка вместо дыры в границе или спеке.
- «Похоже понятно» при маркере `NEEDS CLARIFICATION` или красном stamp.

## Зачем так

Риск автоперехода — долгий заход и правка кода без паузы после tasks. Он принят сознательно ради меньшего контроля с вашей стороны. Страховка: полные скиллы на каждом шаге, одна история, стоп на любом вопросе, оговорка «остановись перед implement».
